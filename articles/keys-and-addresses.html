从助记词到地址：密钥如何转化

用一张派生路线图，读懂助记词、种子、私钥、公钥与地址。

词 → 钥 → 址

助记词不是收款地址，也不是把一个私钥简单翻译成单词。下面以常见的 BIP-39 助记词与 BIP-32 分层确定性钱包为例，解释完整的派生路径。不同钱包可能采用其他备份标准。

一张图看懂派生关系

每一步究竟做了什么？

助记词 → 种子：BIP-39 先对助记词和口令做 UTF-8 NFKD 规范化，再以助记词为密码、mnemonic 加口令为盐，使用 2,048 次 PBKDF2-HMAC-SHA512，得到 64 字节种子。口令不是钱包应用的解锁密码：不同口令会得到不同种子，不存在自动提示“口令错误”的统一机制。

种子 → 私钥：BIP-32 使用 HMAC-SHA512（主密钥生成时密钥为 Bitcoin seed）生成主私钥与链码，再按路径派生子密钥。路径包含用途、币种、账户与索引等信息。相同助记词只有在口令、派生标准、路径等参数一致时，才会恢复到相同账户。

私钥 → 公钥：对常见 BTC / ETH 密钥，私钥是 secp256k1 有效范围内的秘密整数，公钥是曲线上的点。正向计算高效，而已知公钥求私钥在正确实现与足够随机性下计算上不可行。

地址没有一套通用转换公式

比特币 · 以传统 P2PKH 为例

公钥字节 → SHA-256 → RIPEMD-160 → 加网络版本字节与校验和 → Base58Check 编码。

常见外观：1…

原生 SegWit P2WPKH 使用 witness program 与 Bech32（常见 bc1q…）；Taproot 使用经调整的输出公钥与 Bech32m（常见 bc1p…）。它们不能都套用传统地址公式。

以太坊 · 以普通外部账户为例

取未压缩公钥的 64 字节坐标（去掉 04 前缀），做 Keccak-256，取最后 20 字节，以十六进制和 0x 前缀表示。EIP-55 可用大小写加入校验。

常见外观：0x…（40 个十六进制字符）

Keccak-256 与标准 SHA3-256 并不相同。合约账户地址还有 CREATE / CREATE2 等生成规则，不由合约自己的私钥产生。

公开什么，保管什么？

地址用于收款，可以分享，但会暴露相关链上记录。公钥用于验证签名；某些地址类型会在花费时公开公钥。私钥、种子、助记词和助记词口令应保密，拿到它们的人可能控制相应资产。

一个助记词通常可以派生很多账户和地址。只有地址的观察钱包可以查看记录，不能凭地址签名；即使同一个 0x 地址出现在多条 EVM 网络，各链余额也彼此独立。

本页仅解释规则，不生成或收集密钥。不要把真实助记词或私钥输入网页、聊天窗口或任何“在线转换器”。
